ANNA UNIVERSITY SIMULATED CAMPUS RECRUITMENT PORTAL
====================================================

PROJECT PURPOSE
---------------
Build a realistic simulated campus placement / career portal for engineering
students. The portal is intended primarily as a controlled environment for
testing an AI agent that uses Playwright/browser automation to discover job
descriptions, determine eligibility, and apply for campus recruitment drives.

IMPORTANT:
- This is a simulation and is NOT an official Anna University portal.
- Use fictional companies, fictional student data, and fictional drives.
- The UI should look like a professional university placement portal.
- The application must be deterministic enough for automated Playwright testing.
- The portal must support adding new job descriptions without changing frontend code.


1. TARGET STUDENTS
------------------
Support at least these engineering branches:

1. Computer Science and Engineering (CSE)
2. Information Technology (IT)
3. Electronics and Communication Engineering (ECE)
4. Electrical and Electronics Engineering (EEE)
5. Manufacturing Engineering

Academic years:
- Pre-Final Year
- Final Year

Use realistic but fictional Anna University-style academic information.

6. ELIGIBILITY ENGINE
---------------------

Eligibility must NOT be determined only by an LLM.

Create a deterministic eligibility function.

Check:

1. Branch
2. Academic year
3. CGPA
4. Backlogs
5. 10th percentage
6. 12th / Diploma percentage
7. Graduation year
8. Application deadline
9. Drive status
10. Previous application restrictions if configured

Return:

{
  "eligible": true,
  "reasons": [],
  "failedCriteria": []
}

For an ineligible student, give exact reasons.

Example:

{
  "eligible": false,
  "failedCriteria": [
    "Minimum CGPA is 8.00 but student's CGPA is 7.42"
  ]
}


7. APPLICATION WORKFLOW
----------------------

The AI agent must be able to complete this through Playwright.

Workflow:

1. Login
2. Open jobs page
3. Search for jobs
4. Read job card
5. Open JD
6. Extract eligibility criteria
7. Compare against student profile
8. Decide whether application is allowed
9. Click Apply
10. Review application form
11. Confirm application
12. Verify success
13. Open My Applications
14. Verify the application exists

Application form can contain:

- Confirm name
- Confirm student ID
- Confirm branch
- Confirm CGPA
- Resume selection
- Preferred location
- Consent checkbox
- Final confirmation

Do not allow an application if eligibility is false.

13. AGENT EVALUATION SCENARIOS
------------------------------

Create test cases for:

SCENARIO 1:
Agent finds an eligible CSE drive and applies successfully.

SCENARIO 2:
Agent finds a drive requiring CGPA 8.5 when student has 8.36.
Agent must NOT apply.

SCENARIO 3:
Agent finds a drive that accepts ECE but student is CSE.
Agent must NOT apply.

SCENARIO 4:
Agent finds a drive with one allowed backlog and student has one backlog.
Agent may apply.

SCENARIO 5:
Agent finds an expired drive.
Agent must NOT apply.

SCENARIO 6:
Agent finds a drive for Pre-Final Year only while student is Final Year.
Agent must NOT apply.

SCENARIO 7:
Agent finds a cross-disciplinary drive.
Agent should recognize that the student's branch is accepted.

SCENARIO 8:
Agent encounters a newly added job with unfamiliar company and role.
Agent should extract the eligibility criteria from the JD instead of relying
on memorized company information.

SCENARIO 9:
Agent attempts to apply twice.
The second application must be rejected.

SCENARIO 10:
Agent reaches a confirmation screen.
It must verify the details before final submission.

SCENARIO 11:
Job description contains extra natural-language information.
Agent must identify the actual eligibility constraints.

SCENARIO 12:
Two jobs have similar roles but different eligibility requirements.
Agent must evaluate each independently.

21. CORE AGENT TASK
-------------------

The primary benchmark task for the AI agent is:

"Find all campus placement drives for which I am eligible, inspect the job
descriptions, and apply to the appropriate drives. Do not apply to any drive
for which I am ineligible. After applying, verify that each application was
successfully submitted."

The agent should have to:
- navigate the website
- inspect information
- extract structured facts
- compare facts with the student profile
- make decisions
- interact with Playwright
- submit applications
- verify outcomes

The agent should NOT receive the eligibility answer directly as its only
input.

The purpose of this environment is to test whether an AI agent can reliably
perform a multi-step browser task using live website information.

FINAL DESIGN PRINCIPLE
----------------------

The website should be easy for a human student to use, but sufficiently
structured and stateful that an AI browser agent must genuinely:

PERCEIVE -> EXTRACT -> REASON -> DECIDE -> ACT -> VERIFY

The backend should remain the ground truth for eligibility and application
state.

The AI agent should be responsible for navigating the interface, reading the
job description, understanding the requirements, deciding what to do, using
Playwright to perform the action, and verifying the result.
